# Mobile controls and delivery

This pass starts from public source `9ccc0b0` and the complete 515-cell
`senate-20261022-civilian-response` world. The committed Pages descriptor and
hosted release receipt identify the published derivative and source. Original
assets, collision geometry, terrain heights and copyright notices are retained.

## Automatic settings

Touch-first devices select Low without requiring browser memory/core APIs.
Primary mouse devices keep desktop behaviour. Graphics and touch controls have
separate preferences: a controller does not raise phone graphics, and touch
controls can be enabled on a desktop. A manually selected quality or URL preset
continues to override automatic selection.

Mobile Low initially presents at 30 FPS, caps device-pixel ratio at one, starts
at 0.8 render scale and caps the drawing buffer at 1280 by 720 pixels. HTML
controls stay at display resolution. Dynamic resolution uses the selected frame
target, so intentional 33 ms pacing cannot itself cause a downgrade. The pause
menu offers 30/60 FPS and remembers a manual choice. Desktop and review rendering
remain uncapped unless explicitly configured. Physics and encoded input still
use the fixed 60 Hz contract; each 30 Hz presentation normally runs two ticks.

The mobile texture ceiling is 128 MiB including persistent models. Detailed
cell geometry has a 64 MiB budget and a 140 m range; fallback geometry has a
48 MiB budget and a 240 m range. These are visual-cell allocations, not a claim
about total browser/process memory. Scene, pending decode, physics, skeletons,
framebuffers and browser memory require separate accounting. Required collision
and fallback coverage continue to block simulation until safe to advance.

Asset loading prioritizes the player and police and bounds concurrent model
work. Mesh decoding is queued; obsolete queued loads do not fetch or parse.
Distant routine skeleton poses sample at 15 Hz beyond 30 m and 10 Hz beyond
65 m, retaining total authored animation time. Root movement still follows each
presentation. Firing, injuries, falls, death and interaction poses update
immediately. Skin-bound preparation still runs for visible characters; animation
cadence is not a claim that all character presentation work runs at 10 Hz.

## Touch controls and interruptions

The left stick selects walking, running and an outer sprint ring. Dragging the
right-hand free region turns the camera. Aim toggles, and dragging Fire both
shoots and turns, allowing two-thumb movement and firing. Quick Fire/Reload taps
survive until a fixed command consumes them. Jump keeps its existing distinct
press/neutral-tick queue; two quick taps use the existing super-jump window.

Car controls use a steering-only left stick and separate accelerator and
brake/reverse pedals. Braking wins simultaneous pedal input. Enter/exit are
one-shot requests. Horn, handbrake and recovery retain their held semantics.
Commands, aim rays, animation transitions and police rules remain simulation
owned. No touch handler changes position, health, police or physics directly.

Each browser pointer owns its control until release/cancellation. Pause,
backgrounding, graphics loss, streaming waits, player mode transitions and
respawn clear stale touch input. Mode transitions clear input between fixed
ticks within the same rendered frame. Held gamepad inputs must return to neutral
before resuming. The loading screen waits for Start before production simulation
advances; Continue restores canvas focus and audio from a new user gesture.

Controls support mirrored layout, button sizing and look sensitivity, with
English/Finnish labels. Safe-area insets and portrait layouts are supported.
Fullscreen is optional. Full asset notices remain on the loading screen and in
the pause menu; the gameplay attribution line is visually abbreviated to avoid
covering the scene.

## Asset derivation

`tools/world/mobile_delivery.ts` builds a new, content-hashed world without
overwriting its source. Unchanged payloads are hard-linked locally; publication
archives contain only regular files. The HTER v2 terrain representation stores
prior-row integer bit deltas in byte planes before gzip. It preserves every
Float32 height bit and remains compatible with the v1 reader. Runtime data keeps
the parsed immutable height grid for resets, rather than retaining a second
encoded grid alongside it. Source/decoded digest and size limits still apply.

Middle-detail geometry candidates are accepted only after surface, attribute,
outline, protected primitive and image-preservation checks. Unsafe candidates
retain their original payload. Ground candidates have a 1 cm geometric limit;
architectural candidates have a 4 cm limit. Named stairs, bridges, entrances,
retaining structures and landmarks are protected. The build receipt records
actual accepted/rejected candidates; a target simplification ratio is not a
measurement or an assertion that every cell has a distinct middle LOD.

The original global terrain height queries are retained. True terrain fetch
chunking needs a separate authoritative query/residency contract covering distant
spawn checks, police and recovery anchors before it can replace that grid.

The service worker keeps a bounded 96 MiB/128-entry asset cache, measures actual
response bytes, evicts least-recently-used payloads and bounds response-copy work.
Cache failures fall back to network delivery. Disk cache limits are independent
of GPU resource eviction and do not imply full-map offline availability.

## Verification

Meaningful source tests cover device/setting precedence, 30 Hz pacing on
60/90/120 Hz displays, target-aware resolution, real mixer gait/death behaviour,
multi-pointer controls, fast taps, cancellation, paused controls, input mode
boundaries, interrupted audio, terrain bit identity, bounded loading and cache
failure/eviction.

`tools/verify/verify-mobile.mjs` exercises native Chromium touch events against
the ordinary production interface. It checks startup gating, movement/firing,
jump, pause/resume, orientation and drawing resolution. It does not install a
production review API. `--review` permits read-only simulation observations in a
separately compiled review build. `?mobile=1` explicitly selects the same graphics
profile for reproducible review without requiring a touchscreen.

`tools/verify/verify-mobile-journey.mjs` walks to a native car, enters, drives,
steers, brakes, reverses, uses horn/handbrake and exits through native touch
events. Its inspection adapter only observes state and records commands; it does
not teleport, step scripted commands or mutate actors. Replay the recording with
`tools/verify/replay-recording.ts` against the exact world used by the browser.

Browser emulation proves event/layout behaviour and desktop-rendered pacing.
Actual iPhone Safari and Android Chrome performance, memory limits, interrupted
audio behaviour and thermal stability remain physical-device verification work.
No sustained phone FPS guarantee follows from desktop emulation.
