# Web game and asset optimization

Use this route when producing city/actor assets, appending geography, changing streaming, or preparing a web release. Read the current repository's `docs/model-optimization-2026-10-20.md` and `docs/decisions/0022-web-delivery-collision-streaming-and-texture-tier.md`, plus their current implementation and later decisions. The authoring backup may supply missing documents, but its October 20 release IDs, cell counts and timings are historical. Bind the actual deployed baseline and current producer before using them.

## Choose the production path

- For new geography, use the existing new-only delivery preparation and append path (`append_delivery_city.ts`, `lib/delivery-city.ts`, `lib/delivery-city-payloads.ts`). Optimize new native cells, then append to the pinned accepted world. Do not run whole-world optimization over an already optimized release or recompress accepted assets as an incidental expansion step.
- For an original embedded-texture world that genuinely needs its first optimization, `optimize_release.ts` produces a fresh derivative. Inspect its current arguments and input assumptions. Preserve original masters, authoring models, full-resolution sources, accepted payloads and earlier candidates; use independent fresh output paths.
- Apply the existing texture-only/owner-bound facade adapter to later art repairs. Reproduce the selected encoded owner atlas byte-for-byte before enabling a repair, preserve unrelated images/UVs/geometry, and regenerate the affected Standard/Low delivery pair. A repair must not bypass optimization or silently invalidate the Low tier.

## Retain the native transformations and invariants

| Surface | Production strategy and required proof |
| --- | --- |
| City geometry | Compact unreachable append history; remove only exact duplicate opaque oriented faces using complete per-corner attributes. Preserve source Float32 positions, winding, boundaries, outlines, architectural detail and stair/curb creases. Avoid quantization or arbitrary decimation. |
| City LODs | Reuse a tier/alias if a guarded candidate does not qualify. Current intermediate policy requires at least 2% additional triangle reduction. Preserve boundary graphs and verify the native Meshopt error estimate and bidirectional surface samples within the current 1 mm intermediate / 1 cm far limits. Report sample-based bounds accurately; they are not a continuous Hausdorff proof. Remove reversed duplicates only for eligible distant unlit, opaque, double-sided material semantics. |
| Instanced foliage | Reuse the renderer's whole-source tree/card LODs and hysteresis. A preset-specific distance change needs matched settled views and measured triangle/draw costs; retain nearby silhouettes, source instance placement and physical trunks. Do not infer lower texture allocation or download size from earlier geometry LOD transitions. |
| Shared textures | Externalize each exact encoded KTX2/PNG payload once under its content hash. Pin safe relative references; preserve Standard pixels, mip chains and encoding unless a separately scoped art/quality change is authorized and reviewed. Maintain independent disposable texture handles per cell and reference-count shared sources. |
| Low tier | Use the native supported UASTC mip reduction, retaining surviving encoded mip levels, DFD and key/value bytes exactly. Verify Standard-to-Low source mappings independently. Do not substitute unrelated resizes/re-encoding for byte-preserving mip extraction; retain unsupported encodings unchanged. |
| Collision, terrain, graphs | Compress delivery through the existing stored/decoded contract and verify exact round trips, both sizes and both hashes. Preserve collision insertion order and record collision extents from decoded triangles, including geometry beyond owner squares. Compression does not reduce decoded physics or resident terrain memory. |
| Characters and cars | Reuse accepted optimized actors. For changed exports, preserve rig nodes, weights, sockets, clips, names and animation data. The existing raw Meshopt buffer-view route immediately decodes and compares changed views byte-for-byte. Build separate far exteriors only through the current asset-specific contract; protect lamps and required silhouettes. Historical car counts/error ceilings are not generic limits for every asset. |

Validate compressed-format dimension and mip constraints for both Standard and Low, then transcode/upload representative final textures in the actual browser/GPU. A structurally valid KTX2 can still fail a BC7/BPTC upload; pad the atlas and retain chart content/gutters when needed. See the [Khronos BPTC dimension rules](https://registry.khronos.org/webgl/extensions/EXT_texture_compression_bptc/). Keep GPU-compressed allocation estimates distinct from RGBA fallback/mip upper bounds, and match manifest metadata to its runtime consumer's units before enforcing residency budgets.

Verify the relevant implementation rather than introducing a second optimizer. New authored props/trees/landmarks also need appropriate LOD/material/instancing budgets and asset-specific validation; a city packet check does not automatically validate them.

## Further optimization of an assembled world

When further optimization is requested, measure the actual unique manifest closure by asset category first. Audit texture reachability through real GLB materials and texture references, including Standard/Low mappings; do not assume that old-looking hashes or append history imply unused textures. Keep transfer/storage, decoded memory and GPU allocation separate.

Use `compact_delivery_city.ts` for lossless new/changed city cleanup, with decoded active accessors, materials, images, transforms and scenes compared independently. Its default Pages limit stays unchanged; larger private candidates require the existing explicit bounded external mode. Keep accepted visual hashes protected unless the user separately authorizes changing them.

For an explicitly requested storage optimization, `recompress_delivery_simulation.ts` can choose smaller gzip terrain/road/collision representations while retaining every decoded byte, collider order and recorded extent. It accepts an optional hash-pinned candidate cache, validates source identity and bounded decompression, and compares decoded bytes before using a candidate. Record the actual compressor implementation and version: the same nominal gzip level can produce materially different sizes with zlib and zlib-ng. Preserve the source representation when a candidate offers no saving. Use bounded error messages for failed binary comparisons; formatting a large byte-array diff can exhaust memory. Preserve native `.hcol.gz`/`.bin.gz` delivery paths and verify the complete resulting world.

Treat same-resolution RDO as a lossy texture quality change, not a pixel-preserving optimization. Reproduce original source atlases when using the native replay route; measure the paired Standard/Low result. Check every reachable material use before permitting alpha changes, and retain dimensions, mip chains and chart gutters. A small encoded saving does not establish lower GPU memory or better frame times. Inspect actual ordinary and prominent-building views in Standard and Low before adoption; do not reduce resolution merely to meet a hosting cap.

For the native source-atlas route, qualify every final cache with `qualify_native_atlas_rdo_cache.ts` and apply with `--require-source-qualification`. Bind the exact model/config/native index, reconstruct the raw atlas pixels, verify the original native image and baseline mips, and resolve every named input canonically inside the approved source roots. A same-byte unreferenced image is not the selected source. Reject junction escapes. Preserve original cache and producer bytes when correcting historical input-locator roles; publish a separately pinned canonical source proof. Do not rewrite an old receipt to imply it was produced by newer code.

For large batches on Windows, use the applier's bounded `--cache-list` JSON with `--cache-list-sha256` instead of hundreds of repeated path/hash arguments. The list must pair every cache with its source qualification, and final application must retain `--require-source-qualification`. Keep that private locator list outside the output world; public receipts identify it by hash and count.

## Keep optimization connected to the game

Read the current runtime's actual preset and upload/residency limits. In this project these live in the native renderer, streamer, simulation and verification tools; starter tables in the skill are not overrides. Preserve bounded fetch/decode/transcode/upload queues, predicted-motion prefetch, collision streaming by actual extents, cancellation ownership, and loading/retry behavior. A late asset must hold movement at supported ground rather than let actors enter missing collision or invisible required visuals. Retain deferred actor loading and production-only dynamic resolution where present.

Measure stored bytes, decoded bytes, GPU texture estimates/residency, geometry, draws, active colliders, main-thread costs and startup transfer/time separately. Compare cold/warm loading and repeated settled endpoints against the same baseline/device/network/preset. Record moving p50/p95/p99 frame times and worst locations as well as the native FPS gate. Inspect compressed final assets in both Standard and Low: a smaller archive or successful source test is not visual/performance acceptance.

Use the native renderer-backed `textureOwnership()` census for actual uploaded allocation, including complete ownership and measured storage. Logical texture handles, identical-content hashes and `textureMemory().duplicateMiB` do not alone establish duplicate GPU allocation or a deduplication saving. A same-resolution RDO result retains GPU block allocation even when stored bytes shrink.

Paused drop-ins can compare assets at known positions and camera angles, but tick-zero views do not establish populated-NPC, moving or final frame-rate budgets. Keep any mask-free resource fixture private and separate from the publication candidate. Distinguish the measured peak frame from a later capture of its orientation. After a preset/LOD change, repeat affected final Standard/Low checks with actual actors, routes and residency rather than promoting a paused sample as game acceptance.

## Validate and publish the exact pair

1. Bind original native index/model, accepted manifest, optimized index, full producer/dependency closure and final payload inventory. Use the independent native packet/world verifier: validate GLBs, unique owner/crossing IDs, geometry and encoded-mip preservation, all collision/terrain decoded hashes/extents, safe paths and every published payload. Preserve baseline refs outside explicit patches.
2. Traverse final seams on foot and by real vehicle controls, including permitted maximum speed, U-turns and return. Exercise missing/delayed requests, cancellation/retry, unload/reload and tab resume. Run affected Wasted/Busted/civilian/police journeys and same-candidate replays. A paused drop-in proves only the displayed fixture.
3. Build the game against the selected optimized manifest and world base. Verify the original loaded bundle and manifest bytes, production review-hook exclusion, credits, service-worker/cache behavior and rollback tuple. Later asset/runtime edits invalidate affected evidence.
4. Stage the complete app shell and world through the delivery mode's closure/privacy validator. Keep Pages limits unchanged unless an explicitly reviewed design changes that mode. A larger immutable external world requires its own bounded budget and provider-compatible delivery, not an increased Pages constant. Retain exact source/world pairing, CORS, content types, stored/decoded gzip handling, hashed immutable object identity and rollback.
5. When publication is authorized, publish immutable world assets first, verify actual served hashes and browser loading, then promote the matching game shell/descriptor. Check the live default URL, cold/warm load, asset requests and actual controls. Report local-only, committed, merged, uploaded and live-verified evidence separately; do not call an upload or CI exit alone a deployed playable release.

Use the current plan's applicable gates and native commands. For southwest expansion, `tools/verify/verify-delivery-packet.mjs` checks a new-only packet and the release stager validates the assembled world; neither replaces final browser/control evidence. Inspect each CLI before invocation and use fresh evidence directories.
